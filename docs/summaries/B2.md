# Phase B2 summary: master data and Ops onboarding

**Date:** 2026-11-13 · **Branch:** `develop` · **Contract:** `docs/architecture/b2-master-data-contract.md`

## What was done

### API (`apps/api`)

- **Four new modules**, each with its own service, controllers and tests:
  - `tenancy`: companies and departments. Ops onboards and edits; only a Super Admin changes a company's cooldown or low-balance threshold.
  - `fleet`: vehicles, RFID tags and limit rules.
  - `network`: station operators, stations, POS devices and agents.
  - `pricing`: effective-dated fuel prices, national plus station overrides, and a `PriceBook` interface for the fueling engine (B4).
- **Company and station portals read real data**, read-only, with the tenant taken from the signed-in user. Every other tenant's row answers 404.
- **Schema** (`V4__master_data.sql`): every scoped table carries its tenant id and has row-level security. The runtime role has no `DELETE` anywhere and cannot edit a price. A database trigger refuses a child row from another tenant (a vehicle's department, a tag's or limit's vehicle, a device's or agent's station).
- **Tags handled as credentials:** the UID is never stored in clear (AES-GCM + keyed hash), only its last four characters ever leave the API, a tag can be bound once in its life, one active tag per vehicle, and a replacement inherits the cooldown so swapping tags cannot shorten it.
- **One-time secrets:** a device activation code (about 59 bits, 72 hours, keyed hash) and an agent PIN (generated, never trivial, Argon2id) are shown once with `Cache-Control: no-store` and cannot be read back.
- **Plates** are stored as registered and compared through a folded key, so `أ ب ج 4582`, `ابج4582` and `أ ب ج ٤٥٨٢` are the same plate, for duplicates and for search.
- **Prices** are never backdated; the price in force is whichever of the national price and the station override took effect last.
- **Every change is audited** in the same transaction, under the tenant it concerns.
- **A transaction that is not running as `zawed_app` refuses to start**, so a pooler that resets roles or a stray `RESET ROLE` fails closed instead of reading across tenants.
- **User creation** now refuses a company or operator scope that does not exist.

### B1 review fixes (Fable)

- **Row-level security binds the runtime role, not the owner** (`V5__rls_binds_runtime_role.sql`). With `FORCE`, a managed database whose owner is not a superuser would have refused every login. A first fix (a platform scope on each definer function) turned out to be impossible for a non-superuser; the new `NonSuperuserOwnerTests` caught it before it shipped.
- **Rate limits by path first:** a bearer token no longer lifts the sign-in limit. Refresh is limited per session, as the contract says, plus a looser per-address limit.
- **An older enrolment challenge cannot replace an authenticator**; resetting a password or MFA and suspending a user void open challenges.
- Two low findings accepted and recorded in the B1 contract §7.

### Web (`apps/web`)

- Generated API types refreshed from the new OpenAPI description.
- **`npm run seed:api`** creates the demo's master data through the API alone, from the same `createSeedDataset()` the mock demo uses: 3 companies, 5 departments, 50 vehicles with tags, 45 limits, 1 operator, 2 stations, 6 devices, 3 agents and the national prices. The one-time codes and PINs go to a git-ignored file, never to the console. It refuses to run twice.

## How to run and test

```bash
cd apps/api && ./mvnw verify      # API tests on a real PostgreSQL
cd apps/web && npm run check      # typecheck, lint, 171 tests
# Seed a running API (needs a Super Admin access token):
cd apps/web && ZAWED_API_URL=http://localhost:8080 ZAWED_ACCESS_TOKEN=... npm run seed:api
```
