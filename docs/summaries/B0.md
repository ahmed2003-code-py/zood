# Phase B0 summary: Foundations

**Date:** 2026-11-12 · **Branch:** `develop` (not committed yet) · **Plan:** `docs/architecture/implementation-plan.md` §7 B0

## What was done

- **Decisions recorded:** 15 ADRs in `docs/adr/`, from plan §4, updated to the versions actually used.
- **API skeleton** `apps/api`: Spring Boot 4.1.2, Java 25, Spring Modulith 2.1.1, Flyway, springdoc 3.2.0. Maven wrapper committed; no Maven or Docker install needed.
- **Shared kernel** `com.zawed.api.platform` (open module):
  - `Money`, `Volume`, `MoneyMath`: integer piastres and millilitres, half-up rounding, overflow fails. Same test vectors as `apps/web/src/domain/money.ts`, including whitespace handling.
  - `UuidV7` + `IdGenerator`, an injected `Clock`.
  - `ZawedProperties` validated at boot, and `DeploymentGuard`: a deployed instance with a missing or local environment, or localhost/http/wildcard CORS origins, refuses to start.
  - Error contract `ApiError` (`code`, `message`, `retryable`, `requestId`, `field`, `fields`, `params`) on every failure path: security refusals, MVC errors, unexpected exceptions, the container's error dispatch. Messages never echo the request.
  - `X-Request-Id` on every response and log line (also on the error dispatch); unsafe inbound ids are replaced.
  - Security deny-by-default: only `GET /api/v1/health`, `/health/liveness`, `/health/readiness`, `/meta`, `/openapi.json` are public; all other actuator endpoints are switched off.
- **Database:** Flyway baseline `V1__baseline.sql` with the schema rules. Tests and local runs use a real embedded PostgreSQL 18 (ADR 0013).
- **API description:** `apps/api/openapi/openapi.json` is committed, and a test fails when it drifts from the running API.
- **Web:**
  - `VITE_API_MODE=mock|http` switch (default `mock` = the demo, unchanged).
  - `http-client.ts` maps every failure to `ApiRequestError` with a stable `code`.
  - Types generated from the OpenAPI file (`npm run api:types`).
  - `http-api.ts` makes every not-yet-built endpoint fail clearly, naming the phase that builds it.
  - Dev proxy `/api` → `localhost:8080`.
  - Developer page `/dev/api` in Arabic and English.
- **CI:** `.github/workflows/ci.yml`. API: `mvnw verify`. Web: generated types up to date, `npm run check`, build, Playwright E2E.
- **Review:** `zawed-reviewer` reviewed the phase and found 7 issues (no money defects). All were fixed and covered by tests.

## How to run and test

```bash
cd apps/api && ./mvnw verify                  # 52 tests, embedded PostgreSQL, production jar
cd apps/api && ./mvnw spring-boot:test-run    # API on :8080, data in apps/api/.localdb/
cd apps/web && npm run check                  # 154 unit tests, typecheck, lint
cd apps/web && npm run e2e                    # 51 passed, 28 screenshot-capture tests skipped by design
```

To see the web app talk to the API, run the API, then in `apps/web` run `VITE_API_MODE=http npm run dev` and open `/dev/api`.

## Decisions and assumptions

- "يلا ابدا شغل" was taken as approval of plan §12 as recommended. Railway `zawed-dev` was **not** created: it still needs an explicit go-ahead.
- PostgreSQL 18 (embedded binaries 18.6.0) instead of the 17 first written in the ADR draft, so tests match the current release. The deployed database should be 18.
- UUIDv7 is generated by a 40-line class, with no extra library.
- The web shows a developer page only; no product screen uses HTTP yet. That starts in B1 (login) and B2 (data).
- The plan's step "install PostgreSQL locally" was dropped; the embedded database replaces it.
