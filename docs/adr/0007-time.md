# ADR 0007: Time

**Status:** Accepted, 2026-11-12
**Source:** `docs/architecture/implementation-plan.md` §4, decision 7

## Context
PRD §2.3 sets the time rules. Fueling checks depend on time: price schedules in effect at server time, cooldowns, and limits that reset by day or month. Offline transactions are evaluated at the device time. Tests need to control the clock.

## Decision
- Stored times are `timestamptz` in UTC; in code they are `Instant`.
- An injected `Clock` is the only source of "now"; code never calls the system clock directly.
- Limits are evaluated in the station's time zone.

## Consequences
- Cooldown, price-schedule and limit-window tests can set the time exactly.
- Day and month boundaries follow the station's local time, not the server's.
- Every module that needs the time takes the `Clock` from `platform`.
- Offline ingest can evaluate at the device time while the server time stays separate.
